Platform header options — naming a diagram component

The diagram stacks each node as big name → small tracked role (name first, role second, tight leading). Our current SectionBlock always renders kicker (small) before title (big) — so swapping which string goes in which prop fixes the size mismatch but reverses the diagram's order (small-then-big instead of big-then-small).

These four options fix the order too, using only our existing fonts (Syncopate / Space Grotesk / Inter) and color tokens. Each is shown on both a dark section (for “LUCI”) and a light section (for “Systems”), matching how the Platform page actually alternates tone. All are meant to become a reusable SectionBlock variant — not a one-off — so the same pattern can propagate to any future page that names a diagram component. Ordinary section headers (no component name) are untouched by all four options.

Option 1

Stacked lockup — diagram order, no separate eyebrow

Direct port of the diagram's own stack: big name, small tracked role directly under it, tight gap. This is the header — no additional wayfinding label above it. Simplest, most literal match.
